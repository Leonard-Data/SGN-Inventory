# SGN Inventory — MVP foundation

Stack: **Next.js App Router + TypeScript**, **Supabase Postgres/Auth/Storage**, **Vercel**.
Prepared 10 October 2026 for <https://github.com/Leonard-Data/SGN-Inventory>.

This package contains the database foundation, workbook preparation, issue #1 employee access, issue #7's property/contact/address maintenance with correction requests and property history, issue #70's shared-contact detail correction by any active employee, Spec #33's private Property file workspace: actual-content validation, interrupted-upload recovery, company Document categories, authorized category correction and explicit private cover photos, issue #28's protected property detail with an employee's own Vietnam-day activity, issue #29's deliberate owner-contact disclosure with its daily owner-contact count, issue #44's shared flat Property discussion with issue #45's accountable comment removal and moderation, issue #31's manager/admin company employee-by-day activity report, issue #30's personal activity report over a selected Vietnam date range, issue #18's property-detail reservation request with an independent manager/admin decision, and issue #36's recorded asking-price history with separate sale/rent series and an optional retained correction explanation. **It is not a completed inventory application or production release.** Real delivered mailbox/password recovery passed for active, inactive and unlinked identities. The file/category/cover slices were exercised through real authenticated browsers and Supabase Auth/Data API/RLS/Storage on the authorized development project, with synthetic fixture restoration; the shared Property discussion was exercised through real authenticated browsers and the direct Data API/RPC boundary on that project, also with synthetic fixture restoration; the company activity report was exercised through real individual Auth sessions and the Data API/RPC boundary on that project, also with synthetic fixture restoration; the reservation request and independent decision slice was exercised through real authenticated browsers and the user-scoped reservation RPCs on that project, with synthetic fixture restoration, and its review-driven source changes were re-earned at the reconciled design-system head recorded there, while later review fixes remain staging gates ([docs/testing.md](docs/testing.md)); issue #7, issue #30 and issue #70 are implemented in source and still await hosted/browser acceptance; issue #45's removal is implemented in source and its hosted/browser acceptance has not run; issue #36's asking-price history is implemented in source and awaits hosted/browser acceptance. Broader MVP workflows remain planned. Twenty-eight forward migrations are present; no customer workbook import or Vercel deployment was performed.

The first release is a shared property inventory: search addresses and characteristics, inspect owner/broker contacts and documents, record employee activity, and reserve a property after independent approval. An approved reservation records **commission attribution**, with no commission calculation or payout. Rental agreements include month-by-month occupancy/dues and manually recorded rent receipts/refunds. Vietnamese and English UI support is mandatory.

## Required initial setup and local verification

Use Node.js `24.14.0` and npm `11.13.0`. Agent-assisted project setup requires the official GitHub CLI (`gh`), Chrome and all three agent CLIs. Install missing agent CLIs globally and verify them before project work; they are not application dependencies:

```bash
npm install --global gh-axi@0.1.36 chrome-devtools-axi@0.1.39 lavish-axi@0.1.85
gh-axi --version
chrome-devtools-axi --version
lavish-axi --version
npm ci
npm run check
npm run build
npm run dev
```

Copy `.env.example` to ignored `.env.local`, supply the intended dev publishable credentials, expected project reference, private file-validation key and exact local origin, then run `npm run check:env`. Open `/login` (VI by default) or `/login?lang=en`; successful login loads the saved employee preference. Spec #33's isolated worktree used `http://localhost:3038`, leaving the user's existing server untouched. See [executed acceptance](docs/testing.md) for scoped browser/Supabase evidence and private fixture prerequisites.

Authenticate the official GitHub CLI for GitHub work. Use `gh-axi` for GitHub, `chrome-devtools-axi` for browser work and `lavish-axi` for visual decisions/reports; consult current command help before use. See [required agent setup](docs/setup.md#1-tooling-first) for prerequisites, `PATH` guidance and authorization boundaries. Optional agent hooks/plugins are not required.

For the full local Supabase stack, install Docker, inspect `npx supabase start --help` and `npx supabase db reset --help`, then start/reset a **local** project. These migrations are for a fresh database; do not apply them unreviewed to an existing CRM.

Workbook profiling (Python 3.11+):

```bash
python -m pip install -r requirements-import.txt
python scripts/prepare_workbook.py /secure/Databases.xlsx --out /secure/import-run
```

Add `--stage` only to create private local staging records. Never commit the workbook, staging files, customer contacts, passwords, legal files or credentials.
